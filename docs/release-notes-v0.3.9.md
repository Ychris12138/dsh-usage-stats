# v0.3.9

## 账户与界面

- 新增千问个人 Token Plan 的显式授权入口和账户用量卡片（#166）。已在 DSH Web 和 Desktop 测试个人版授权、用量读取和重启后复用。团队版、国际版及不同套餐的显示口径尚未验收；授权失效后的本地移除逻辑已做模拟回归（#167）。
- DeepSeek Account 在 `dsh web` 缺少 Desktop 客户端版本时可尝试向宿主查询余额（#170 / #171）。在第三方打包宿主中，缺省客户端版本时优先读取宿主的 client module release 版本，服务缺席或失败时继续使用已有回退（#175 / #174）。#170 原补丁曾获得真实 Web 账户反馈；最终候选的 Web 与 DS Bot 账户验收仍待完成。
- 声明式余额和订阅监控可从新版 DSH 的生效配置发现已注册路由的查询地址（#172 / #162）。DSH Web 0.2.2-rc.3 中已用本机模拟额度服务验证；报告者的 0.2.1-rc.5 环境及实际供应商仍待复核。显式 `usageBaseURL` 配置和网络限制不变。
- 侧栏徽标将上游限制状态显示为「受限」，不再暗示额度小于等于 5%；实际用量比例仍按上游数据展示（#169）。
- 侧栏入口按可用宽度和同排入口数量选择文字或图标态，不再修改共享底栏的换行样式（#176）。DS Bot 等隐藏原生底栏的宿主可显式启用备用悬浮入口（#174）；具体宿主的槽位可用性和视觉表现仍待验收。
- DeepSeek Account 记录真实发出的失败余额查询；缺少必要客户端信息导致未发出请求时，显示安全原因并保留未尝试状态（#174）。
- OpenCode Go 官方已公布用量接口；403 现在提示检查订阅及访问权限，401 仍表示凭据被拒绝（#140）。

## 待验证与已知范围

- DS Bot 备用入口依赖宿主挂载 `shell.overlay`，账户版本来源、快捷键、入口位置和重启后偏好均需实际宿主验证（#174）。
- 侧栏容量自适应遵循非官方社区约定；候选需结合多插件、宽窄侧栏和挂载顺序进行界面验收。不遵循该约定的旧插件可能仍造成布局冲突（#176）。
- #168 需求未明确通知类型；本版没有新增通知开关。
- 火山方舟个人 Coding Plan 适配器需要显式配置官方 CLI，OpenCode Go 路径与方舟适配器均缺真实订阅对账（#74 / #140）。
- Web 搜索用量草案 #133 不包含在本版内；上游目前没有可核实的响应级用量事件。也未新增已发布的 Providers Hub `creditBalance` 集成。

最终候选仍待完整测试、重新打包和安装验收。先前候选的 CI 与 tarball 哈希不适用于新提交；模拟与隔离验证不能证明真实账户余额、扣费或授权。
