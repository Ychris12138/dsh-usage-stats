# 共享底栏 wrap 生命周期（#176）

2026-11-24，针对 [Issue #176](https://github.com/Ychris12138/dsh-usage-stats/issues/176) 中的共享容器竞争准备的局部修订。

旧实现的卸载函数无条件恢复先前的 inline flexWrap。如果其他参与者在其后写入 wrap-reverse 或 nowrap，卸载 usage-stats 就会擦除这个新值。另一个可复现情况是同一 bundle 的两个实例同时使用底栏：第二个实例看到 wrap 后不登记所有权，第一个实例卸载就会提前撤销布局。

修订对同一 bundle 内的实例按共享 host 计数，仅最后一个实例释放时尝试恢复；如果当前值已不再是本插件写入的 wrap，就保留后来写入的值。释放幂等，释放后可重新挂载。行为回归覆盖重叠实例、重复清理、其他参与者后写和重新挂载；扩展测试在未修改主线上失败。

## 范围与剩余验证

这不是完整的多插件布局仲裁。无法仅凭 CSS 值判断其他插件是否也写过相同的 wrap；也没有跨 bundle 的共同所有权协议。现有共享容器覆盖仍然保留，直到替代方案在真实场景确认。

[社区 §20](https://github.com/abworks-dev/dsh-plugin-ui-conventions/blob/main/conventions/20-sidebar-footer.md) 是非官方约定，可作为容量测量和形态收缩的参考，而非官方宿主保证。此次未修改按钮几何、未采用整排容量切换，也未宣称符合完整约定。

下一步应在真实宿主中检查一个、两个、三个入口，侧栏宽/窄态，动态加载与卸载的顺序，以及 #21 / #82 的历史场景，再评估移除 wrap 覆盖。仅需版本、插件组合、操作顺序和可见性结果；不需要账户凭据。

该修订与 #174 中 DS Bot 主动隐藏原生底栏的问题不同，不提供 body 浮动入口。#175 的版本来源修订也仍需对应提交的真实 DS Bot 账户验收。
